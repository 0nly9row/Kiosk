# 설계 조건
1. 화면별 역할 분리
- 하나의 UI에 기능을 몰지 않는다.
- 각 UI가 담당할 역할을 나눈다.

2. UI 변경 책임 분리
- 화면 변경은 해당 UI가 담당한다.
- 외부에서는 Property로 값을 전달한다.
- 실제 화면 변경은 해당 UI 내부에서 처리한다.

3. 반복 기능 Utility 분리
- 반복되는 공통 기능은 Utility로 분리하여 재사용한다.

4. UI 간 동작은 Event 사용
- 하위 UI는 동작 발생을 알린다.
- 상위 UI가 Event를 받아 다음 동작을 결정한다.

5. 데이터와 UI 분리
- 데이터는 Model로 관리한다.
- UI와 데이터의 책임을 분리한다.

6. 메서드는 기능 단위로 분리
- 하나의 UI 내부에서도 기능별로 메서드를 나눈다.
